# Decisions log

One line per design or technical decision, with the reason.

## M0 — Skeleton

- Monorepo via npm workspaces (no pnpm/turbo): fewest tools; packages import each other's TS source directly.
- Packages export `src/index.ts` with no build step: Vite, Vitest and tsx all consume TS natively, so there's nothing to keep in sync.
- Exact-pinned toolchain: TypeScript 7.0.2, Vite 8.3.6, Vitest 5.1.0, PixiJS 8.22.0, tsx 4.23.15: the doc asks for an exact PixiJS pin; pinning everything keeps builds reproducible.
- `sim` and `bots` compile with `lib: ES2022` and `types: []`: DOM and Node APIs are type errors there, not just lint warnings.
- Sim lint is a small script (`scripts/lint-sim.mjs`), not ESLint: it bans Math.random, Math transcendentals, `**`, timers, Date, browser/Node globals, Map/Set and for…in, with no plugin setup.
- PRNG is PCG32 (oneseq), with state stored as two uint32 halves: plain JSON-serializable data, no BigInt in the hot path; verified against a BigInt reference in tests.
- Trig uses Horner-evaluated Taylor series with fdlibm-style quadrant reduction, not a lookup table: only IEEE +,−,×,÷,√, so it is bit-identical everywhere and accurate to ~1e-16; a table would need Math.sin to build it.
- State hash is FNV-1a over a canonical, key-sorted walk of the state (numbers hashed by their float64 bytes): it covers any plain-data state without per-field code.
- `step(state, inputs)` mutates the state in place: avoids allocating per tick; callers that need snapshots clone (`structuredClone` keeps the hash).
- Terrain keeps a per-chunk revision counter in sim state instead of a dirty set: the renderer and the bot nav grid each compare against their own last-seen revision, with no shared mutable "consumed" flag.
- Material colors, toughness and friction live in `content/materials.json`; the sim ignores color.
- M0 maps are a JSON sidecar with a frame border; the PNG material importer arrives with real maps (M1/M2).
- Fixed-step loop caps at 5 ticks/frame and drops the backlog after a stall (tab switch) instead of fast-forwarding.
- Camera in M0 fits the whole map at the largest integer scale (pixel art); the follow camera with look-ahead comes in M1.
- The design doc stays in Claude Docs and `docs/README.md` links to it, so there's no copy here to go stale.

## M1 — Flight sandbox

- Approved defaults for two open questions: wall impacts damage ships (with `tuning.ship.wallDamage` as a match option to turn it off) and rotation stays snappy (angular velocity set directly, no angular momentum).
- Angle convention: 0 = nose up, clockwise positive, matching screen coordinates and Pixi's rotation.
- The hull collider is a circle of radius size/2, sampled at 12 ring points plus the centre: rotation can never push a ship into a wall, and the triangle drawn on screen fits inside it.
- Collision uses substeps of at most 2 px plus a 5-step bisection to the surface; the normal is minus the sum of the colliding sample directions. That's enough to stop tunnelling at 2000 px/s through a 3 px wall (tested).
- Impacts below `restSpeed` don't bounce, so ships settle on the ground instead of jittering.
- Sliding friction is material friction × `contactFriction`, so ice (0.05) slides far and dirt (0.6) grips.
- Pads are stamped into the terrain as a 4 px slab of a new indestructible `pad` material (id 5, green), so they show up and can't be carved without special cases.
- Landed = grounded on a pad, nose within 20° of upright, speed ≤ 40 px/s. An upright touchdown on a pad below `safeImpactSpeed` (160 px/s) does no damage, even above the general wall threshold (90 px/s).
- **Flag:** the doc's "Balanced hovers at ~60% duty" doesn't match its own table (thrust 300 vs gravity 120 is 40% duty). I kept the table's numbers since they are the stated starting points; tune it with the panel.
- Map drag defaults to 0.4/s (top speed under full thrust ≈ 750 px/s); the doc gives no number.
- Respawn picks the spawn point farthest from living ships (ties go to the lowest index), as the match-flow section says; it's simple enough to do now.
- Sim config (tuning, hulls, materials) is copied into `SimState.config`, so the tuning panel edits the live match and the hash covers it.
- Content JSON is checked with a tiny built-in schema validator (`sim/validate.ts`) rather than JSON Schema + a library: no dependency, and the same checks run in Node and the browser.
- Maps are PNGs whose colors match `content/materials.json`; off-palette pixels snap to the nearest material, so hand edits in any image editor import cleanly. Node uses a small built-in PNG codec (node:zlib); the browser decodes through a canvas.
- `tunnels.png` is generated by a seeded script (`tools/src/genTunnels.ts`), but the committed PNG is the source of truth and can be hand-edited.
- The terrain part of the state hash is cached by terrain revision: hashing 600 KB every tick made the 4-ship determinism test take 29 s, and it now takes a fraction of a second.
- Assisted steering is gamepad-only for now (stick direction = target nose angle); keyboard keeps classic rotate, since a keyboard can only give 8 directions.
- The M1 sandbox player uses both keyboard halves and the first gamepad at once; per-player device assignment comes with the M3 join screen.
- The debug single-step key moved from `.` to `]`, since `.`/`/` sit near the right-hand keyboard layout.
- Camera zoom is the integer that keeps about 300 world px of height visible (2× at 720p, 3× at 1080p), keeping pixel art crisp.
